---
title: datasets.yaml
description: Define business datasets and their typed, user-facing fields.
---

`datasets.yaml` lists the datasets and fields that callers can query, in the
words your business uses. It contains no database, table or column names: those
go in [`sources.yaml`](/catalog/sources).

The descriptions matter. They are what a person or an AI agent reads to decide
which field to use, so write them for someone who has never seen your tables.

```yaml
api_version: yodb/v0.1

catalog:
  name: acme_data
  version: 1

datasets:
  customer:
    description: A company with a commercial account.
    aliases: [client, account, organization]
    fields:
      id:
        type: id
        description: Stable customer identity.
      name:
        type: string
        description: Customer company name.
        aliases: [company, organization_name]
        example_values: [Acme, Globex]
      account_key:
        type: uuid
        description: A source key used by an approved relationship.
        visibility: internal
      profile:
        type: text
        description: Customer profile text suitable for semantic search.
        semantic_eligible: true
```

## Top-level attributes

| Path | Required | Allowed value | Meaning |
| --- | --- | --- | --- |
| `api_version` | Yes | `yodb/v0.1` | Catalog-format version. |
| `catalog.name` | Yes | Lower snake case | Catalog identifier. |
| `catalog.version` | Yes | Positive integer | Immutable catalog version. |
| `datasets` | Yes | Non-empty mapping | Datasets keyed by lower-snake-case names. |
| `datasets.<name>.description` | Yes | String | Business definition. |
| `datasets.<name>.aliases` | No | List of strings | Synonyms for people and agents. |
| `datasets.<name>.fields` | Yes | Mapping | Fields keyed by lower-snake-case names. |

## Field attributes

| Attribute | Required | Default | Meaning |
| --- | --- | --- | --- |
| `type` | Yes | — | Logical YoDb type. |
| `description` | Yes | — | Business definition. |
| `aliases` | No | `[]` | Synonyms. |
| `example_values` | No | `[]` | Safe examples or enum-like values. |
| `visibility` | No | `public` | `public` or `internal`. |
| `semantic_eligible` | No | `false` | Allows a `semantic` condition on this text field; see [Semantic filter](/query/semantic-filter). |

| Type | Use |
| --- | --- |
| `id` | Stable YoDb dataset identity. |
| `string` | Short text such as names and statuses. |
| `text` | Long-form content. |
| `int` | Whole numbers and counts. |
| `float` | Measurements, scores, and prices. |
| `bool` | True/false values. |
| `timestamp` | An instant in time. |
| `uuid` | UUID values that are not the dataset's logical `id`. |
| `json` | Flexible structured metadata. |
| `bytes` | Small binary values or references. |

Every dataset must contain a public `id` field with `type: id`. The physical
column supplying it is configured later in `sources.yaml`.

## Internal fields

A field with `visibility: internal` is mapped and checked like any other, and
YoDb can use it to match rows for a relationship. Callers cannot use it: a query
that selects or filters on it is refused with `field_not_accessible`, and it is
left out of what an AI agent is shown over [MCP](/reference/mcp). `yodb catalog`
still lists it, because that command is for the person who maintains the
catalog.

Use it for a key that links two datasets but that callers should not read. Note
that a relationship which joins on an internal field cannot be followed by a
query yet; see [Joins](/query/joins).
