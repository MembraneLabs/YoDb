title: YoDb
description: A typed, explainable federated data layer for relational, semantic, and graph queries.
---

YoDb gives applications and agents one typed way to query connected data
sources without migrating their data.

The first version is read-only. It is designed for:

- relational reads from PostgreSQL;
- semantic filtering with PostgreSQL, pgvector, and a verification model;
- bounded graph traversal through PostgreSQL edge tables or Neo4j.

YoDb does not expose raw SQL, Cypher, vector index names, or database
credentials to callers. Instead, a developer defines a small catalog of
datasets, sources, and relationships.

## What V0.1 does

- Strict three-file catalog loading, and read-only inspection of PostgreSQL that
  refuses to open a catalog that does not match the databases.
- Typed queries over one logical dataset whose fields live in one or several
  PostgreSQL databases: filters, ordering, paging, assembled by logical ID, with
  a plan you can inspect.
- [Joins](/query/joins) between two datasets over a relationship you declare, even when they
  live in different databases or on different servers.
- A cost-based planner that uses database statistics, falling back to fixed rules.
- A semantic filter (a natural-language condition judged by a verifier you
  supply), optionally shortlisted by vector search, with the vectors in the same
  database or a separate one.
- A `yodb` command and a Python front door, `yodb.connect`.
- An [MCP server](/reference/mcp), `yodb mcp`, that lets an AI agent discover and query a catalog
  without SQL or physical names.

Graph traversal, cursor paging, aggregation, and the Neo4j adapter are not
implemented; see [Limits](/reference/limits).
