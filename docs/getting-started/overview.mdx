## Build a catalog in three steps

1. Define business datasets and fields in `datasets.yaml`.
2. Map only approved source resources and physical fields in `sources.yaml`.
3. Define approved dataset relationships in `relations.yaml`.

```text
catalog/
├── datasets.yaml
├── sources.yaml
└── relations.yaml
```

The catalog has no user-authored mapping files beyond these three documents.
Read [YAML syntax](/catalog/yaml-syntax) for the object and list notation used
in examples.

## Static catalog loading

Static loading validates YAML structure and cross-file references. It is safe
to run in CI because it never resolves `connection_ref` or connects to a
source.

```python
from yodb import load_catalog

catalog = load_catalog("catalog")
print(catalog.datasets.keys())
```

## Inspect and validate PostgreSQL

The implemented PostgreSQL path is separate from static loading:

```text
connection reference → connection resolver → bounded PostgreSQL pool
                     → read-only inspection snapshot → catalog validation report
```

The inspector reads metadata, not business rows. It discovers tables/views,
columns, native types, primary and unique keys, foreign keys, indexes,
extensions, and pgvector facts. The validator then checks that the catalog's
resource, field, type, and identity claims match that snapshot.

See [PostgreSQL inspection](/inspection/postgres) for the integration contract.

From the repository root, run the test suite with:

```bash
PYTHONPATH=src python3 -m unittest discover -s tests -v
```

Install the project before using PostgreSQL pooling:

```bash
python3 -m venv .venv
.venv/bin/pip install -e .
```
