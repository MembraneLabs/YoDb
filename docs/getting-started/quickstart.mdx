This page uses the sample in `examples/shop`: a shop whose data is in three
PostgreSQL databases. By the end you will have queried all three as if they
were one. It takes about five minutes.

You need Python 3.11 or newer, and Docker to run the sample databases.

## 1. Install

From a checkout of the repository:

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install .
```

This installs the `yodb` command and the `yodb` Python package. Two optional
extras add more: `pip install ".[mcp]"` for the
[server for AI agents](/reference/mcp), and `pip install ".[semantic]"` for a
local model used by the [semantic filter](/query/semantic-filter).

## 2. Start the sample databases

```bash
cd examples/shop
./setup.sh
```

The script starts one PostgreSQL server in Docker with three databases, and
prints three `export` lines. Paste them into your shell:

```bash
export YODB_CONN_CRM="host=localhost port=55440 dbname=crm user=yodb_ro password=yodb_ro"
export YODB_CONN_BILLING="host=localhost port=55440 dbname=billing user=yodb_ro password=yodb_ro"
export YODB_CONN_SUPPORT="host=localhost port=55440 dbname=support user=yodb_ro password=yodb_ro"
```

This is how YoDb learns how to connect. The catalog never holds a password. It
names each database with a short `connection_ref`, such as `crm`, and YoDb reads
the connection string for it from the environment variable `YODB_CONN_CRM`.

| Database | Table | Holds |
| --- | --- | --- |
| `crm` | `customers` | each customer's name, country and sign-up date |
| `billing` | `subscriptions` | each customer's plan |
| `support` | `tickets` | support tickets, each with a customer ID |

## 3. Read the catalog

The catalog is the directory `catalog/`. It has three files, and each answers
one question.

**`datasets.yaml`: what data is there?** It names the datasets and their fields
in business terms. There are no table names here.

```yaml
api_version: yodb/v0.1
catalog: {name: shop, version: 1}
datasets:
  customer:
    description: A customer of the shop.
    fields:
      id:        {type: id,        description: Customer identity.}
      name:      {type: string,    description: Name.}
      country:   {type: string,    description: Two-letter country code.}
      plan:      {type: string,    description: Billing plan. Empty when the customer has none.}
      signed_up: {type: timestamp, description: When the customer signed up.}
  ticket:
    description: A support ticket.
    fields:
      id:          {type: id,     description: Ticket identity.}
      customer_id: {type: id,     description: The customer who raised the ticket.}
      subject:     {type: string, description: Subject line.}
      status:      {type: string, description: Where the ticket stands.}
      priority:    {type: int,    description: From 1 for low to 5 for urgent.}
```

**`sources.yaml`: where does each field live?** It maps every field to a table
and column in one database. Note that `customer` appears under two sources:
`crm` supplies most of its fields and `billing` supplies `plan`. Both map the
customer's `id`, which is how YoDb matches their rows.

```yaml
api_version: yodb/v0.1
sources:
  crm:
    kind: postgres
    connection_ref: crm
    read_only: true
    datasets:
      customer:
        resource: public.customers
        identity: [id]
        fields:
          id:        {physical_name: customer_id}
          name:      {physical_name: name}
          country:   {physical_name: country}
          signed_up: {physical_name: signed_up}
  billing:
    kind: postgres
    connection_ref: billing
    read_only: true
    datasets:
      customer:
        resource: public.subscriptions
        identity: [id]
        fields:
          id:   {physical_name: customer_id}
          plan: {physical_name: plan}
  # the support source maps the ticket dataset the same way
resolution:
  customer:
    identity_source: crm
    field_sources: {id: crm, name: crm, country: crm, signed_up: crm, plan: billing}
  # and the same for ticket
```

**`relations.yaml`: how do datasets connect?** It declares that a ticket belongs
to a customer, and which two fields match.

```yaml
api_version: yodb/v0.1
relationships:
  customer_has_ticket:
    from: customer
    to: ticket
    description: A support ticket belongs to the customer who raised it.
    cardinality: one_to_many
    direction: bi
    implementations:
      - from: {source: crm, field: id}
        to: {source: support, field: customer_id}
```

[Concepts](/getting-started/overview) explains these terms, and
[Catalog overview](/catalog/overview) is the full reference.

## 4. Check the catalog

Two commands check it. The first needs no database: it reads the files and
lists what can be queried.

```bash
yodb catalog catalog/
```

```text
catalog shop v1: 2 dataset(s), 3 source(s)

customer  - A customer of the shop.
  id         id                 from crm
  name       string             from crm
  country    string             from crm
  plan       string             from billing
  signed_up  timestamp          from crm

ticket  - A support ticket.
  id           id                 from support
  ...
```

The second connects to the databases and checks that every table and column in
the catalog really exists, with a compatible type.

```bash
yodb validate catalog/
```

```text
catalog shop v1: active
  crm                  valid
  billing              valid
  support              valid
```

If anything does not match, such as a missing column, YoDb lists the problems
and refuses to run queries.

## 5. Ask a question

A query is a JSON object. It names a dataset and its fields. It never names a
database or a table.

```bash
yodb query catalog/ '{
  "from": {"dataset": "customer"},
  "select": ["name", "country", "plan"],
  "where": {"field": "country", "op": "eq", "value": "UK"},
  "order_by": [{"field": "name", "direction": "asc"}]
}'
```

```text
id   name             country  plan
---  ---------------  -------  ----
c01  Ada Lovelace     UK       pro
c03  Alan Turing      UK       free
c10  Tim Berners-Lee  UK       pro
(3 rows)
```

`name` and `country` came from the `crm` database and `plan` from `billing`.
The `id` is always returned.

Three ways to pass a query: as text (above), as a file with `@query.json`, or
on standard input with `-`. Add `--format json` or `--format jsonl` for output a
program can read.

## 6. Join two datasets

`traverse` follows the relationship from `relations.yaml`. This finds US
customers with open tickets, most urgent first:

```bash
yodb query catalog/ '{
  "from": {"dataset": "customer"},
  "select": ["name"],
  "where": {"field": "country", "op": "eq", "value": "US"},
  "traverse": [{
    "relationship": "customer_has_ticket", "as": "ticket",
    "select": ["subject", "priority"],
    "where": {"field": "status", "op": "eq", "value": "open"}
  }],
  "order_by": [{"field": "ticket.priority", "direction": "desc"}, {"field": "name", "direction": "asc"}],
  "page": {"first": 3}
}'
```

```text
id   name               ticket.id  ticket.subject           ticket.priority
---  -----------------  ---------  -----------------------  ---------------
c07  Barbara Liskov     t11        Two-factor not working   5
c02  Grace Hopper       t03        App crashes on export    5
c05  Margaret Hamilton  t08        Data missing after sync  5
(3 rows)
```

You get one row per customer and ticket pair. The ticket's fields are prefixed
with the `as` name. See [Joins](/query/joins).

## 7. See how a query runs

`yodb explain` takes the same arguments as `yodb query` and shows the plan
without running it:

```bash
yodb explain catalog/ '{"from": {"dataset": "customer"}, "select": ["name", "country", "plan"],
  "where": {"field": "country", "op": "eq", "value": "UK"}}'
```

```text
plan in_memory_record_assembly   fingerprint 43bbd4d538e5
  remote_scan            @crm          fields=id,country,name pushed=country
  remote_scan            @billing      fields=id,plan
  record_assembly        @coordinator  fields=id,country,name,plan schedule: anchor:crm -> optional:billing*
  ...
```

Read it top to bottom. YoDb reads `crm` and asks it to apply the `country`
filter (`pushed=country`). It then reads `billing`, but only for the customers
it found (the `*`). `@coordinator` means YoDb itself, which puts the rows
together. See [How queries are planned](/query/planning).

## 8. Make a mistake on purpose

```bash
yodb query catalog/ '{"from": {"dataset": "customer"}, "select": ["nam"]}'
```

```text
error [field_not_found] at select[0]: Unknown field 'nam' on dataset 'customer'.
```

Every error has a code, the place in the query, and a message. See
[Errors](/reference/errors).

## 9. Use it from Python

```python
import yodb

with yodb.connect("catalog/") as db:
    result = db.query({
        "from": {"dataset": "customer"},
        "select": ["name", "plan"],
        "where": {"field": "country", "op": "eq", "value": "UK"},
    })
    for row in result.rows:
        print(row["id"], row["name"], row["plan"])
```

See [Python API](/reference/python).
