The `yodb` command is installed with the package. Each subcommand takes the
catalog directory first.

```text
yodb catalog  CATALOG                 what can be queried (no database needed)
yodb validate CATALOG                 inspect the real sources and check the catalog against them
yodb explain  CATALOG QUERY           the plan: sources, pushdown, read order, strategy
yodb query    CATALOG QUERY           run it
yodb mcp      CATALOG                 serve the catalog to an AI agent over MCP
```

`CATALOG` is a directory holding `datasets.yaml`, `sources.yaml` and
`relations.yaml`. `QUERY` is JSON text, `@file.json`, or `-` for standard input.
`python -m yodb` is the same command.

## What each command prints

`yodb catalog` lists every dataset and field, and the source each field comes
from. It needs no database.

```text
catalog shop v1: 2 dataset(s), 3 source(s)

customer  - A customer of the shop.
  id         id                 from crm
  plan       string             from billing
  ...
```

`yodb validate` connects to each database and reports whether the catalog
matches it.

```text
catalog shop v1: active
  crm                  valid
  billing              valid
  support              valid
```

`yodb query` prints a table by default. `--format json` prints the rows and the
query's fingerprint; `--format jsonl` prints one row per line.

```text
id   name             plan
---  ---------------  ----
c01  Ada Lovelace     pro
(1 rows)
```

```json
{"rows": [{"id": "c01", "name": "Ada Lovelace", "plan": "pro"}],
 "query_fingerprint": "fa01beba5083..."}
```

`yodb explain` prints the plan, one step per line, without reading any data.
See [How queries are planned](/query/planning) for how to read it.

## Connections

Each catalog `connection_ref` is read from the environment variable
`YODB_CONN_<REF>` (upper-cased; every non-alphanumeric character becomes `_`;
`crm-readonly` is `YODB_CONN_CRM_READONLY`). The value is a libpq connection
string or URI. Alternatively `--connections FILE` names a YAML or JSON mapping:

```yaml
crm-readonly: "host=db1 dbname=crm user=yodb_ro password=..."
billing-readonly: "postgresql://yodb_ro:...@db2/billing"
```

Keep the file out of version control and readable only by you.

## Options

| Option | Commands | Meaning |
| --- | --- | --- |
| `--connections FILE` | validate, explain, query, mcp | connection strings by reference |
| `--no-statistics` | validate, explain, query, mcp | plan with the fixed rules only |
| `--statement-timeout SECONDS` | validate, explain, query, mcp | database statement limit when `--timeout` is not given (default 60) |
| `--timeout SECONDS` | query, mcp | time limit for the whole query (`mcp`: for each query, default 60) |
| `--format table\|json\|jsonl` | query | output format |
| `--json` | catalog, explain | machine-readable output |
| `--debug` | all | show a traceback for an unexpected failure |

## Exit status

| Status | Meaning |
| --- | --- |
| 0 | success |
| 1 | a YoDb error, printed to standard error as `error [code]: message` (see [Errors](/reference/errors)) |
| 2 | bad usage (an unreadable query or connections file, or `yodb mcp` without the `mcp` package) |
| 3 | an unexpected failure (the exception type is printed; `--debug` shows more) |

Error messages never contain connection strings, passwords, SQL or values.

A query with a `traverse` step ([joins](/query/joins)) runs and explains the same way; its output rows carry
the traversed fields prefixed with the `as` name (`ticket.subject`).

`yodb mcp` runs until its client disconnects and writes only protocol messages to standard output; see
[MCP server](/reference/mcp).

The command does not configure the [semantic filter](/query/semantic-filter),
which needs providers: use the Python API for that.
